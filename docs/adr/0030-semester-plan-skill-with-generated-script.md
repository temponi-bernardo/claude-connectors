# 0030 — Semester plan skill renders a fixed template from validated JSON

- **Status:** Accepted
- **Date:** 2026-11-23
- **Related:** ADR 0006, ADR 0020, ADR 0022

## Context

The `/planejamento` skill (canvas-puc) publishes and keeps updating a "Plano do Semestre" artifact: an HTML page
with risk per course, a study plan, a timeline and checklists whose ticks must survive every update. Routines
republish it twice a day without a person watching. Text from Canvas, email and WhatsApp is untrusted and goes
into the page. A model that rewrites the HTML on each run drifts in layout, can break the page, can lose the
checklist ids (and so the ticks) and can insert raw third-party text as markup.

## Decision

The skill never writes HTML. It writes one JSON document; a script shipped in the skill
(`scripts/plan.mjs`) validates it (zod shape plus points, dates, ids and references), reuses the previous
version's ids, carries over items the new version left out, and injects the JSON into a fixed template
(`assets/plan-template.html`) whose runtime renders everything with `textContent`. Both files are generated by
`npm run build` from TypeScript in `connectors/canvas-puc/src/plan/` and versioned, like `server/remote.js`;
`pr:check` and the unit tests fail when they are stale. The page runtime has its own tsconfig with the DOM lib.

## Alternatives considered

| Alternative                                  | Why not                                                                             |
| -------------------------------------------- | ----------------------------------------------------------------------------------- |
| Claude writes or edits the HTML on every run | Layout drift, broken pages, lost ids (lost ticks), raw third-party text as markup   |
| Hand-written JS script and HTML in the skill | Escapes the repository rules (types, tests, coverage, docs) for security-heavy code |
| A remote tool on the Canvas Worker           | Needs a deploy and network for what is pure local transformation; plan data leaves  |

## Consequences

- Positive: same page on every run, validated data, stable ids, no raw HTML from third parties, tested code.
- Negative / accepted costs: generated files in the plugin (about 180 KB); the skill needs Node to run the
  script; a second tsconfig for the page runtime; `jsdom` as a dev dependency.
- Docs that change: STRUCTURE, PROCESSES (P05, P20), FUNCTIONS, ARCHITECTURE, TESTING, connector README,
  CHANGELOG.
