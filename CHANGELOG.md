# Changelog

All notable changes are recorded here. Format [Keep a Changelog](https://keepachangelog.com/en/1.1.0/);
versions follow [SemVer](https://semver.org/). Version sections are generated by release-please
(local CLI, ADR 0006) from the commits; the "Unreleased" section is maintained by hand.

## [Unreleased]

### Security

- Data isolation audit ([docs/security/isolation.md](docs/security/isolation.md)), with tests that prove two users
  served by the same Worker isolate only see their own data.
- Every OAuth, `/pair` and Gmail link seal now names its connector (`aud`); a token issued by one connector is
  refused by another, even with the same key. Tokens issued before this change keep working until they expire.
- Canvas: sending messages, replying and submitting are now opt-in per person, with an unticked box on the connect
  page. **Connections made before this change are read-only until reconnected** (tick the box to get the write
  tools back).
- Gmail: opening a `link_account` link now shows whose connector receives the account and asks for confirmation;
  the confirmation only works from that page in that browser, and then Google asks the owner to confirm it is
  them (identity only) before asking for Gmail access. A forwarded link opened by anyone else links nothing.
- WhatsApp: `ALLOWED_EMAILS` must have exactly one email (everyone listed would read the same WhatsApp); there
  is no override.
- Tool errors, login and result pages and logs redact tokens and credentials (`redactSecrets`); logs also mask
  emails. The login pages no longer send CORS headers.

Canvas plugin released as `canvas-puc` 3.1.0 (details in `connectors/canvas-puc/CHANGELOG.md`).

### Added

- Canvas: `submit_file_assignment` submits a file to assignments that only accept uploads (`online_upload`). The
  file comes inside the call, as plain text (`encoding: "text"`, e.g. a `.txt` report) or base64, up to 5 MB. It
  refuses before uploading anything when the assignment does not take files, the extension is outside
  `allowed_extensions` or the file is empty or too large; then it runs Canvas's three-step upload and submits
  the file. Writes only, with confirmation in the chat (ADR 0026). The `prepare-submission` skill uses it instead
  of sending the user to Canvas.
- Canvas: links and media of every HTML content are no longer lost. `get_assignment`, `get_page`, `get_discussion`
  (prompt and each post) and `list_announcements` keep the text readable but write each link as `title [link N]`
  and return a new `links` field: `{ n, type, title, url, file_id?, course_id?, page_url?, assignment_id?,
  media_id?, provider?, followable }`, with `type` `file`, `video`, `image`, `page`, `assignment`, `discussion`,
  `quiz`, `module`, `canvas` or `external`. It reads the Rich Content Editor's `data-api-endpoint`, file links with
  `/preview`, `/download` and `?verifier=`, Canvas media (`/media_objects/`, `/media_attachments_iframe/`), iframes
  and links of YouTube, Vimeo, Panopto, Stream/SharePoint and Google Drive, and images. Only the Canvas host and
  those video providers are `followable`; other links are reported, never fetched (ADR 0025).
- Canvas: `raw_html: true` on `get_assignment`, `get_page`, `get_discussion` and `list_announcements` returns the
  original HTML (`description_html`, `body_html`, `message_html`) for debugging.
- Canvas: `list_linked_files(course_id)` lists every file and video referenced by the course's assignments, pages,
  forums, announcements and module items, once per file id, with where each one appears.
- Canvas: `list_files` takes `include_linked: true` to add the files only linked from the content
  (`linked_only: true`) and say how many it was missing.
- Canvas: inbox (conversations) tools. `find_recipients` finds teachers, TAs and classmates by name and returns their
  user ID, `list_conversations` lists the inbox (inbox, unread, starred, sent, archived) and `get_conversation` reads a
  conversation without marking it as read. With writes enabled, `send_message` starts a new conversation with up to 20
  people (numeric user IDs only, so a message never reaches a whole course by accident) and `reply_to_conversation`
  answers an existing one; both are `destructiveHint` and Claude confirms the exact text first.

### Changed

- Canvas: `download_file` and `read_file_text` open files hidden from `list_files`. They accept `file_id`, a Canvas
  file `url` (from `links`) or both, plus `course_id`, and try `GET /courses/:cid/files/:id`, `GET /files/:id` and
  the link's `verifier` in that order. When every endpoint fails, the error lists each one with its status and the
  reason (hidden, locked, no permission, not found) instead of a generic failure. Verifiers never appear in errors
  or logs.
- Canvas: `list_files` adds a note that Canvas does not list hidden or locked files to students and how to reach
  them (`links`, `list_linked_files`).
- Canvas: a 401 that only denies one resource (`"status": "unauthorized"`) is no longer reported as an expired
  token.
- HTML is converted with a real parser (`htmlparser2`) instead of regexes, in Canvas, Gmail and Word extraction;
  entities are fully decoded.
- Canvas: `download_file` returns files above 8 MB in parts of raw bytes, with the new optional `offset` and
  `length` arguments (8 MB at most per call). Each answer gives the byte range and the next offset; the caller
  joins the parts. Claude's client drops tool results above ~16 MB, so a single 15–70 MB answer failed (ADR 0024).
- Canvas: `download_file` now accepts files up to 70 MB (was 10 MB). In remote mode the file is streamed from
  Canvas to Claude as base64 without being held whole in the Worker's memory, and the download is cut at 70 MB
  even if Canvas reports a smaller size (ADR 0023). Claude itself may still reject very large documents.
- Source code is English (ADR 0021): comments, JSDoc, test names, logs and every user-facing string of the three
  connectors. The Canvas login page ("Connect Canvas to Claude"), the Gmail consent and link pages, the WhatsApp
  `/pair` page (start over now asks to type `ERASE` instead of `APAGAR`), Worker configuration errors, OAuth error
  descriptions and the Go bridge messages are translated. Gmail forwards use `---------- Forwarded message
  ----------` with `From:`/`Date:`/`Subject:`/`To:` and replies quote `On <date>, <sender> wrote:`; the WhatsApp
  bridge names the account's own messages `"You"` (was `"Você"`) and stores polls as `Poll: <name>`.
- **BREAKING** — Plugins: the 12 plugin skills have English names and content, so their slash commands changed
  (no aliases, ADR 0021). Canvas: `/config-canvas` → `/setup-canvas`, `/resumo-semana` → `/weekly-summary`,
  `/preparar-entrega` → `/prepare-submission`, `/estudar-disciplina` → `/study-course`. Gmail: `/config-gmail` →
  `/setup-gmail`, `/triagem-email` → `/triage-inbox`, `/achar-documento` → `/find-document`, `/resumir-conversa`
  → `/summarize-thread`. WhatsApp: `/config-whatsapp` → `/setup-whatsapp`, `/resumo-whatsapp` →
  `/whatsapp-summary`, `/pendencias-whatsapp` → `/whatsapp-pending`, `/buscar-whatsapp` → `/search-whatsapp`.
  Canvas skills cite the English tool names (`whoami`, `upcoming_assignments`...); skills still answer in the
  user's language and trigger on Portuguese requests.
- **BREAKING** Canvas: the 18 tools are renamed to English, with no aliases: `quem_sou_eu` → `whoami`,
  `listar_cursos` → `list_courses`, `proximas_entregas` → `upcoming_assignments`, `listar_tarefas` →
  `list_assignments`, `ver_tarefa` → `get_assignment`, `notas` → `get_grades`, `avisos` → `list_announcements`,
  `modulos` → `list_modules`, `ver_pagina` → `get_page`, `arquivos` → `list_files`, `ler_arquivo_texto` →
  `read_file_text`, `baixar_arquivo` → `download_file`, `discussoes` → `list_discussions`, `ver_discussao` →
  `get_discussion`, `calendario` → `get_calendar`, `buscar` → `search`, `entregar_tarefa_texto` →
  `submit_text_assignment`, `responder_discussao` → `reply_to_discussion`. Input parameters (`dias` → `days`,
  `filtro` → `filter` with `all`/`upcoming`/`past`/`unsubmitted`/`overdue`, `termo` → `term`...) and output fields
  (`titulo` → `title`, `enunciado` → `description`, `nota` → `score`...) are English too (ADR 0021). Saved tool
  permissions that use the old names must be updated.
- All tools of the three connectors now carry an English `title` and MCP hints: read tools are `readOnlyHint`,
  tools that send, submit, overwrite or delete are `destructiveHint` (Canvas submit and reply, Gmail send, reply,
  forward, send/update/delete draft, trash and unlink, WhatsApp `send_message`). Tool descriptions and error
  messages are in English, and each MCP server announces the version of its `plugin.json`.
- Site: the public GitHub Pages site is in English (ADR 0021). The privacy policy moves to `privacy.html` and the
  terms to `terms.html`; the old `privacidade.html` and `termos.html` addresses redirect to them. The three plugins'
  `privacyPolicyUrl` point to the new page.

- Canvas: when the Canvas token behind a refresh token was deleted or expired in Canvas, the OAuth refresh now
  answers `invalid_grant` instead of new tokens that fail on every tool call, so Claude asks to connect again.
  Canvas outages (network errors, 5xx) still keep the session.
- Gmail: the protected resource metadata `resource_name` is now "Gmail (multi-account)" (it still said
  read-only).
- Privacy policy: corrected what Gmail stores and sends to Google, added a WhatsApp (self-host) section and the
  GitHub issues contact. Connectors Directory readiness is documented in `docs/DIRECTORY-LISTING.md`.
- Plugins: each `plugin.json` now has an explicit `version` (`canvas-puc` 3.0.0, `gmail` 1.0.0, `whatsapp` 1.0.0),
  `license`, `keywords`, `homepage`, `author.url`, `privacyPolicyUrl` and a 512 px icon (`.claude-plugin/icon.png`);
  descriptions are in English. Marketplace entries gain `category` and `tags`. release-please manages each plugin
  as its own package and bumps the `plugin.json` version; `pr:check` runs `claude plugin validate --strict` on the
  marketplace and every plugin (ADR 0022).
- Plugins: each marketplace entry now points at `connectors/<name>/plugin/`, which holds only the manifest,
  `.mcp.json`, skills and a short README. Server code, tests, `Dockerfile` and bundles no longer reach the
  user's plugin cache (ADR 0020). Update the marketplace once to pick it up.
- WhatsApp: **sending enabled** (`ENABLE_SEND = "true"` in `wrangler.toml`) for any contact or group;
  `SEND_ALLOWLIST` is now optional (empty = any recipient). Explicit confirmation for each message
  (`confirmed_by_user`) and the hourly limit (`SEND_MAX_PER_HOUR`) remain. Media sending is left out (ADR 0015).
- Gmail: the connector requests the `gmail.modify` scope instead of `gmail.readonly`. Accounts linked earlier keep
  reading; to send or organize, `list_accounts` shows `write_access: false` and the tools ask to link the account
  again with `link_account`. The owner must add the scope to the Google Cloud consent screen before deploying.

### Fixed

- WhatsApp: `whatsapp_status` waits for the reconnection (up to `SYNC_WAIT_MS`, like the read tools) instead of
  reading the status at once. Right after the container woke up from idling it reported `connected: false`,
  `sync_complete: false` and `last_event_at: null`, which looked like a dropped connection. When the wait runs out,
  the status now carries a `warning` saying it is still connecting or syncing.
- WhatsApp: pairing dropped on every deploy or container restart. The session backup never reached R2
  (`pipeTo` between the bridge body and the `FixedLengthStream` fails on Workers); the copy is now done chunk by
  chunk (`pumpInto`). In addition, the bridge sends the snapshot on its own as soon as the session changes (paired,
  connected or logged out), without waiting for use or for the container to sleep.
- WhatsApp: the plugin no longer embeds the server (`${user_config.server_url}`) and ships only the skills; each
  person connects their own server as a custom connector on their account, which works on claude.ai, the app,
  mobile, Cowork and Claude Code. The field lived only on the computer and the plugin installed by the organization
  on claude.ai had another URL, so the **Link** button refused the login before opening GitHub. `npm run build` now
  rejects `${user_config.*}` in `.mcp.json` and accepts a plugin without `.mcp.json` (ADR 0018).

### Added

- WhatsApp: `send_message` accepts a group JID (`@g.us`) and replies quoting a message from the same chat
  (`reply_to_message_id`).
- Gmail: **full management** through Claude, on any linked account (`account`): send (`send_email`), reply
  keeping the thread (`reply_email`), reply all (`reply_all_email`), forward with the original attachments
  (`forward_email`), drafts (`list_drafts`, `create_draft`, `update_draft`, `send_draft`, `delete_draft`), mark as
  read/unread (`mark_read`), archive (`archive`), star (`star`), labels (`update_labels`), trash and restore
  (`trash`, `untrash`). No permanent deletion. The tools carry MCP annotations (`destructiveHint` on sending and
  deletion) so Claude asks for confirmation (ADR 0019).
- Shared MCP tools (`src/mcp/tools.ts`) accept `annotations`.
- **`/config-canvas`**, **`/config-gmail`** and **`/config-whatsapp`** commands (plugin skills): guided setup of
  each connector in the chat, with connection, browser login, account linking or pairing, and a test.
- Usage skills in the plugins: Canvas (`/resumo-semana`, `/preparar-entrega`, `/estudar-disciplina`), Gmail
  (`/triagem-email`, `/achar-documento`, `/resumir-conversa`) and WhatsApp (`/resumo-whatsapp`,
  `/pendencias-whatsapp`, `/buscar-whatsapp`). They work in the chat, in Cowork and in Claude Code.

### Added

- `SessionEnd` hook (`session-end-handoff.sh`): on `/clear` or session end without a handoff, generates
  `docs/STATE.md` via `claude -p` if there was an edit or commit after the last handoff (ADR 0017).

## [0.1.0](https://github.com/temponi-bernardo/claude-connectors/releases/tag/v0.1.0) (2026-11-14)

### Changed

- Canvas (v2.0.0): the connector runs only in the cloud. The marketplace plugin points at the remote server
  (`https://canvas-puc-remote.bftemponi.workers.dev/mcp`) and login is through the OAuth page, pasting the Canvas
  token once. It works the same on claude.ai, Cowork, mobile and Claude Code (ADR 0013).
- `npm run pack`/`pack:all` became `npm run build`: it validates that each connector's `.mcp.json` is remote
  (`http` with `https://`) and generates the `server/remote.js` used by the Dockerfile.

### Added

- **Personal WhatsApp** connector (`connectors/whatsapp`, self-host template on Cloudflare Workers + Containers,
  ADR 0015): `whatsapp_status`, `list_chats`, `get_messages`, `search_messages`, `search_contacts` and `get_media`;
  sending (`send_message`) behind `ENABLE_SEND`, off, with an allowlist and an hourly limit. On-demand container
  (sleeps after 5 min), session in an encrypted backup on R2, `/pair` page with code or QR, and owner login through
  GitHub.
- Remote connector: login delegated to an identity provider (GitHub with `ALLOWED_EMAILS`), in addition to login
  by pasted credential (`src/remote/github-login.ts`).
- **Remote Gmail connector** (`connectors/gmail`, ADR 0014 and ADR 0016): public and multi-user. Whoever installs
  the `gmail` plugin signs in with their own Google account (already linked at login) and sees only the accounts
  they linked; more accounts come in through a single-use link (`link_account`) and leave with `unlink_account`,
  which revokes access at Google. Read tools `list_accounts`, `search_threads`, `get_thread`, `get_message`,
  `list_labels` and `get_attachment_text` (PDF, Word, HTML and text), with `account` (`all` where it makes sense).
  OAuth 2.1 with `@cloudflare/workers-oauth-provider`, refresh tokens encrypted (AES-256-GCM) in Workers KV, limits
  of 120 req/min per session and 30 req/min per IP on public routes. Optional `ALLOWED_EMAILS` for private mode.
  Runs only on demand (`npm run gmail:deploy`).
- Site: the privacy policy covers Gmail, with the Google API Services Limited Use disclosure.
- `src/core/pdf.ts`: dependency-free PDF text extraction (compressed streams, object streams and ToUnicode maps).

- Public site on GitHub Pages (`https://temponi-bernardo.github.io/claude-connectors/`) with a home page, privacy
  policy and terms of use, to use as the production service link; the Canvas manifest points to it (ADR 0013).
- Canvas: the plugin now works in Claude Code cloud sessions. `.mcp.json` sets `NODE_USE_ENV_PROXY=1`, and Node
  uses the environment proxy, which injects the Canvas token. Just fill the plugin's "Access token" field with any
  text (e.g. `proxy`).

- Canvas: `baixar_arquivo` tool, which brings the content of a course file (PDF, slides, image; up to 10 MB) into
  the conversation, in the local and remote connectors.
- Canvas: `ler_arquivo_texto` now also reads Word documents (`.docx` and `.doc` 97-2003), with no new
  dependencies (`src/core/zip.ts`, `src/core/cfb.ts`, `src/core/word.ts`).
- The remote Canvas connector renews the PUC token's validity on its own at each OAuth refresh: reconnecting every
  month is no longer needed (ADR 0011).
- Connectors repository created from `template-new-project`: docs as the source of truth, AST-based checks, TDD,
  Claude Code hooks and skills.
- **Canvas PUC Minas** connector (`connectors/canvas-puc`, v1.3.0): 20 tools (assignment schedule, assignments,
  grades, announcements, modules, pages, files, forums, calendar, search, submit assignment and reply to forum).
- Canvas login through a Chrome/Edge window with silent session renewal; token only as a fallback.
- `npm run pack` / `pack:all`: packs each connector into a lean `.mcpb` extension (esbuild bundle, ~3 MB).
- `npm run pr:check`: local PR gate in place of CI.
- Repository as a Claude **plugin marketplace**: each connector installs through "Add marketplace", with a
  configuration form and updates through commits.
- **Remote Canvas connector** (`server/remote.js`, ADR 0009): HTTP server with OAuth to use Canvas on claude.ai,
  Cowork and mobile, authorizing with the Canvas access token; published on Cloudflare Workers
  (`npm run worker:deploy`) or on any Docker host.

### Fixed

- Remote Canvas connector on Cloudflare Workers: calls to Canvas send `User-Agent` (without it Canvas answered
  403) and the login page allows the return to claude.ai in the CSP (before, the Connect button did nothing).

### Removed

- Canvas: the whole local part. Removed the stdio server (`server/index.js`), the `.mcpb` extension, browser login
  (`playwright-core`, session in `~/.canvas-puc/`) and the `conectar_canvas` and `desconectar_canvas` tools. The
  plugin configuration form is gone too.
- GitHub Actions (CI, CodeQL, release-please in a workflow): checks and releases run locally, at no cost.
